# STTP DApp Frontend

React-based web application for the STTP (Secure Token Presale Protocol) platform. This frontend provides a user interface for creating presales, participating in Dutch Auctions, trading in Liquidity Bootstrap Pools (LBP), and managing token vesting.

## Overview

The frontend is built with Create React App (CRA) and CRACO, providing a modern React development environment with custom build configuration. It connects to Ethereum smart contracts via wagmi and RainbowKit, enabling wallet connectivity and transaction management across multiple wallet providers.

## Technology Stack

- **React** 18.2.0 - UI framework
- **wagmi** ^2.12.17 - Ethereum React hooks
- **RainbowKit** ^2.2.9 - Wallet connection UI and provider management
- **React Router** ^7.9.6 - Client-side routing
- **Tailwind CSS** - Utility-first CSS framework (via CRACO)
- **ethers.js** ^6.13.0 - Ethereum interaction library
- **React Query** (@tanstack/react-query) - Server state management
- **Recharts** ^3.5.1 - Chart visualization
- **Framer Motion** ^12.23.24 - Animation library

## Prerequisites

- **Node.js** >= 18.x

- Deployed smart contracts (see `../contract/README.md`)
- Contract ABIs and addresses in `src/abi/addresses.json` (generated during contract deployment)

## Installation

```bash
npm install
```

## Environment Variables

Create a `.env` file in the `client/` directory (optional):

```bash
# WalletConnect Project ID (optional)
REACT_APP_WALLETCONNECT_PROJECT_ID=your_project_id_here
```

> **Note**: The application works with a default WalletConnect project ID if not specified. For production use or to avoid rate limits, obtain a project ID from [WalletConnect Cloud](https://cloud.walletconnect.com).

## Available Scripts

### Development

```bash
npm start
```

Starts the development server at `http://localhost:3000`. The application will:
- Automatically open in your default browser
- Hot-reload on file changes
- Connect to the local Hardhat node (chainId 31337) by default

### Production Build

```bash
npm run build
```

Creates an optimized production build in the `build/` directory. The build process:
- Minifies JavaScript and CSS
- Generates source maps (disabled by default via `GENERATE_SOURCEMAP=false`)
- Optimizes assets for production deployment

### Testing

```bash
npm test
```

Runs the test suite using React Testing Library and Jest. Tests are executed in watch mode during development.

## Contract Integration

The frontend reads contract addresses and ABIs from `src/abi/addresses.json`, which is automatically generated by the contract deployment script (`../contract/scripts/deployAll.ts`).

**Important**: Deploy contracts before starting the frontend:

```bash
cd ../contract
npm run deploy:all
```

This generates the required ABI files and contract addresses that the frontend uses to interact with deployed contracts.

## Wallet Connection

The application supports multiple wallet providers through RainbowKit:

- **MetaMask**
- **Rabby Wallet**
- **Coinbase Wallet**
- **WalletConnect** (mobile wallets)
- **Safe** (Gnosis Safe)
- **Other EIP-6963 compatible wallets**

Users must connect their wallet to the correct network (Hardhat Local for development, or supported mainnets/testnets).

## Supported Networks

The application is configured to work with the following networks:

- **Hardhat Local** (Chain ID: 31337) - Default for development
- **Sepolia** (Testnet)
- **Mainnet**
- **Base** (Layer 2)
- **Base Sepolia** (Testnet)

Network configuration is defined in `src/config/wagmi.js`.

## Key Features

### Presale Management
- Create new presales with configurable parameters
- View all deployed presales
- Monitor presale status and statistics

### Dutch Auction
- Commit phase: Submit sealed bids with cryptographic commitments
- Reveal phase: Reveal committed bids and verify allocations
- Automatic price discovery through Dutch auction mechanism
- Merkle proof verification for whitelisted participants
- Real-time auction status and price tracking

### Liquidity Bootstrap Pool (LBP)
- Place bids in the LBP pool
- Real-time price charts and weight schedule visualization
- Pool state monitoring (reserves, fees, weights)
- Adaptive fee system display
- Oracle-driven pause indicators

### Token Vesting
- View vesting schedules and unlock timelines
- Claim vested tokens
- Visual progress indicators and charts
- Cliff period and linear unlock visualization

### IPFS Integration
- Automatic loading of whitelist Merkle proofs from IPFS
- Bonus allocation data fetching
- Gateway fallback mechanism for reliability

## Custom Hooks

The application includes extensive custom hooks for contract interactions:

**Auction Hooks:**
- `useAuctionData` - Fetch auction state and parameters
- `useAuctionHandlers` - Transaction handlers (commit, reveal, claim)
- `useAuctionEvents` - Event subscription and filtering

**LBP Hooks:**
- `useLbpData` - Pool state and reserves
- `useLbpActions` - Bid placement and pool interactions
- `useRealtimeLbpData` - Real-time price and weight updates

**Vesting Hooks:**
- `useVestingData` - Escrow state and unlock information
- `useClaimHandler` - Token claiming logic

**Utility Hooks:**
- `useTransaction` - Transaction status tracking
- `useAccount` - Wallet account management

## Troubleshooting

**Application doesn't connect to contracts:**
- Verify `src/abi/addresses.json` exists and contains contract addresses
- Ensure contracts are deployed to the correct network
- Check browser console for specific error messages

**Wallet connection fails:**
- Verify wallet extension is installed and unlocked
- Check that the correct network is selected in the wallet
- Ensure Hardhat node is running (for local development)

**IPFS data not loading:**
- Verify internet connection (required for public gateways)
- Check browser console for IPFS fetch errors
- Some presales may not have IPFS data configured

## Build Configuration

- Tailwind CSS processing

- Source map control
